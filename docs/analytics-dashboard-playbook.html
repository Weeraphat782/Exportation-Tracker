Website Analytics Dashboard

Implementation playbook for the OMGEXP admin /analytics page — reusable on other sites.
Reference stack: Next.js + GA4 Data API + GTM on the public marketing site.
Version: July 2026

1. Architecture

The dashboard is not an embedded Google Analytics UI. It is a custom admin page that pulls aggregated metrics from the GA4 Data API using a Google Cloud service account, then renders charts with Recharts.

Visitor → Marketing site (GTM snippet) → dataLayer events → GTM → GA4 property
Staff → /analytics page → GET /api/analytics/ga (Bearer auth) → ga-data.ts → GA4 Data API → JSON → charts
Contact form → attribution in localStorage → Supabase (CRM) — separate from GA4, not shown on this dashboard yet

Two halves: (A) code in your repo embeds GTM and pushes events; (B) configuration in GTM UI + GA4 Admin (tags, triggers, custom dimensions, referral exclusions) is not in git.

2.3 Site filter logic

Reports include traffic where either:

  • hostName = MARKETING_GA_HOSTNAME (new Astro site at www.omgcargo.tech), or
  • pagePath begins with GA_PUBLIC_PATH_PREFIX (legacy /site/* on cargo.omgexp.com)

Staff-only routes (e.g. /dashboard, /login) are excluded unless they match the above.

3. Manual setup (GTM + GA4 Admin)

  1. Create a GA4 property and web data stream for your marketing domain.
  2. Create a GTM container; add GA4 Configuration tag with your Measurement ID (G-XXXX).
  3. Add Custom Event triggers for generate_lead, cta_click, contact_click.
  4. Add GA4 Event tags mapping dataLayer parameters to event parameters.
  5. In GA4 Admin → Custom definitions, register event-scoped dimension form_name (parameter form_name). Without this, “By form” breakdown fails.
  6. Enable Google Analytics Data API in Google Cloud; create a service account; download JSON key or copy email + private key to env.
  7. GA4 Admin → Property access management → add service account as Viewer.
  8. GA4 Admin → Data streams → Configure tag settings → define unwanted referrals (e.g. your own domain) to fix self-referral like omgcargo.tech / referral.
  9. Mark generate_lead as a key event in GA4 if you want it in standard reports.

5. Accuracy limits

  • Processing lag: Standard reports lag 24–48 hours; Realtime/DebugView are immediate.
  • Undercount: Ad blockers, no-JS, Safari ITP — typically 10–30% of sessions missing client-side.
  • Lead events vs CRM: GA4 counts events; Supabase stores submissions with attribution JSON — two systems, two numbers.
  • Double submits: eventCount increments per event; GA4 dedupes transaction_id only for purchase, not generate_lead.
  • Legacy /site traffic: If old marketing routes stay live, metrics mix two sites until you redirect or narrow filters.
  • Self-referral: Cross-domain hops without referral exclusion inflate “referral” and split sessions.

6. Verification checklist

  1. GTM Preview → submit test form → see generate_lead with form_name.
  2. GA4 DebugView → same event within seconds.
  3. GA4 Realtime → active user on marketing hostname.
  4. Admin /analytics → KPIs load (not “Analytics not configured”).
  5. If a section shows Data unavailable with an error string, fix GA4 config (usually missing custom dimension).
  6. Run node --experimental-strip-types scripts/ga-range.test.mjs after changing date logic.
  7. Compare lead events (GA4) vs contact rows (Supabase) over the same week — expect difference, not parity.

7.2 PEM key troubleshooting

If the API returns OpenSSL DECODER routines::unsupported, the private key env is malformed. The codebase normalizes quotes, literal \n, and Windows \r — but the key must still be a valid PEM block.

7.3 Legacy /site vs new domain

OMG currently serves marketing on both www.omgcargo.tech (Astro) and /site/* on the Next app. Top pages may show /site/login alongside /. Options: 301 legacy to new domain (SEO + cleaner analytics), or set GA_PUBLIC_PATH_PREFIX to a path that no longer receives traffic once migrated.

7.4 PDPA note

GTM/GA4 cookies require disclosure in your cookie policy. Attribution keys in localStorage should be listed there too. Consent Mode v2 is recommended for new deployments in regulated markets.
